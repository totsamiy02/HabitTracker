# HabitTracker

Личный офлайн-трекер привычек для Android. Один выполненный день добавляет привычке одну клетку. Клетки складываются в плоскую квадратную мозаику. Пропуски не стирают прогресс.

## Что реализовано

- Android-приложение с одним модулем `:app`, Kotlin, Jetpack Compose, Material 3 и палитрой «Слива и лаванда». Минимальная версия — API 26. Интерфейс на русском, строки в ресурсах. Постоянный `applicationId` — `com.yaroslav.habittracker`, у debug отдельный суффикс `.debug`.
- **«Сегодня»** — список простых ежедневных привычек. При создании вводим название и необязательное описание. На экране привычки выполняем отметку кнопкой «Отметить сегодня» или нажатием на клетку с плюсом. Room хранит привычки и отметки. Пара «привычка + локальная календарная дата» уникальна.
- **Мозаика** — Compose Canvas строит рисунок по числу отметок. Квадрат начинается с 4 × 4. На 17-й выполненный день появляются столбец справа и ряд снизу, прогресс становится 17 из 25. Порядок и координаты прежних клеток сохраняются. История хранится независимо от рисунка.
- **«Настройки»** — логотип, описание, версия, обновление и экспорт. Через системный выбор файла сохраняется JSON с `formatVersion: 1`, привычками, датами отметок и параметрами мозаики. Экспорт берёт согласованный снимок базы. Системное резервное копирование данных приложения отключено.
- **Проверка обновлений** — публичный запрос к последнему стабильному GitHub Release репозитория `totsamiy02/HabitTracker`. Релиз использует тег `v<versionName>` и один файл `HabitTracker-<versionName>-build<versionCode>.apk`. Клиент сравнивает `versionCode`. Релизная сборка скачивает APK, проверяет пакет, версию и подпись и передаёт его системному установщику. Debug позволяет проверить наличие обновлений. Установка из приложения рассчитана на релиз с постоянной подписью.

Основной код разделён на `habits/`, `settings/` и `ui/` в пакете `com.yaroslav.habittracker`. Хранилище — `HabitDatabase`, исходная схема Room хранится в `app/schemas/`. Разработка идёт в `dev`, стабильная ветка — `main`. Журнал — [CHANGELOG.md](CHANGELOG.md). Визуальные черновики храним вне репозитория.

GitHub Actions из `.github/workflows/android.yml` запускает тесты и lint. На пуше в `main` после проверок workflow подписывает APK и публикует релиз. Версию задаём в Gradle и описываем в журнале. Ключ хранится вне репозитория, CI получает его из GitHub Secrets.

## Что ещё предстоит

- Развить привычки: редактирование, расписание по дням недели, просмотр и коррекция истории, ручной ввод времени. Привычка с целью по времени считается выполненной, когда сумма сессий достигает цели.
- Добавить таймер, календарь и связанные планы. Сессия таймера сохраняется один раз, включая завершение в фоне. После сворачивания или блокировки восстанавливается правильный остаток. Экран «Сегодня» позже покажет планы и таймер, а календарь — планы и фактические записи.
- Расширить копию после добавления сессий и планов. Восстановление должно проверять весь файл, показывать состав и запрашивать подтверждение замены данных. Для будущих пользовательских предпочтений используем DataStore. Блокировка по биометрии или системному PIN опциональна.
- До постоянного использования проверить на телефоне обновление между двумя подписанными APK и сверить историю и мозаику. Схему Room обновляем миграциями с сохранением данных.
- Позже — собственные рисунки и импорт PNG, напоминания, повторяющиеся планы, заметки, архив, Pomodoro, статистика и виджет.

## Рабочие ограничения

Бюджет 0 ₽. Основные функции работают офлайн, сеть нужна для обновлений. Без аккаунта, сервера и публикации в Google Play. Сборка на Mac через Gradle Wrapper с JDK Android Studio, APK проверяется вручную на телефоне. Для отдельных компонентов подходит Compose Preview.

Перед работой используй [правила разработки](CHAT_PROMPT.md). Актуализируй существующие разделы при изменении поведения или архитектуры. Историю выпусков держи отдельно.
